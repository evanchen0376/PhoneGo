# PhoneGo 端侧网课弹题助手方案

## 目标

让 PhoneGo 在安卓手机上运行内置模型。网课视频播放中弹出必须作答的试题时，自动读取题干和选项、作答并提交，然后确认视频已经恢复播放。局域网模型服务可以用于前期验证，但目标版本的答题推理在手机上完成。

## 现有能力与改造点

- Android 设置已支持自定义 API 地址和单独指定视觉模型。Python 客户端通过 OpenAI 兼容接口调用模型，因此可以先用电脑上的本地多模态模型验证任务流程。设置页目前只做纯文本连通性测试，截图理解和截图加工具调用需要单独验证。 [Android 模型设置](../android-app/app/src/main/java/com/phoneagent/app/MainActivity.java#L1655) · [模型客户端](../phoneagent/core/llm.py#L55) · [连接测试](../phoneagent/server.py#L926)
- PhoneGo 已能读取界面结构、截屏和执行点按。已知页面可以用地图重放操作，陌生页面可以交给视觉模型决定下一步。网课流程固定，适合让程序负责识别播放器状态、提交和检查续播，模型集中处理题目。 [设备接口](../phoneagent/devices/base.py) · [Agent 执行流程](../phoneagent/core/agent.py#L747) · [视觉操作循环](../phoneagent/core/agent.py#L1422)
- 手机端需要增加推理和模型加载能力。能够直接读到题干和选项时，优先用文本模型。题目只显示为图片或公式时，再根据样本决定是否需要端侧视觉模型。

## 难度判断

固定一个 App，覆盖可读取的单选题并确认续播，预计是中等难度。跨平台、多题型和长时间无人值守会增加适配和恢复成本。

影响最大的因素是答案所需的信息。常识题或依据题干即可回答的题目，可以先验证端侧小模型。若题目追问老师刚讲过的例子，需要把相关字幕或讲义片段与题目一起输入模型。课程只提供音频时，还要考虑转写和上下文提取，工程量会上升。实际准确率和端侧性能待真机验证。

## 第一版建议

限定一个网课 App、可从界面读取的单选题和手机端推理。流程为**发现弹题 → 读取题干和选项 → 生成选项 → 提交 → 核实播放进度继续推进**。遇到题目读不全、找不到提交按钮或提交后未续播时，保留现场并报告失败步骤。

1. 收集目标 App 的播放中、弹题和提交后页面样本。确认题干和选项能否从界面结构读到，课程有无字幕，以及题目是否依赖刚讲过的内容。
2. 用同一批样本验证答题正确率，再到真机验证弹题检测、提交和续播。可先用局域网模型排查流程，端侧版本用同一批题复测。
3. 记录弹题检测率、答题正确率、提交后续播率和从弹题到续播的耗时。连续运行时再观察手机内存、发热和耗电。
